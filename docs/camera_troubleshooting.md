# USB 카메라 연결 및 영상 수신 오류 해결 기록

## 1. 개발 환경

본 프로젝트에서는 Microsoft LifeCam HD-3000 USB 카메라를 사용하여 책상 위 사물을 실시간으로 촬영한다.

개발 환경은 Windows 11과 WSL2 기반 Ubuntu 24.04이며, Ubuntu 환경에서 ROS2 Jazzy와 OpenCV를 이용하여 카메라 영상을 처리하도록 구성하였다.

### 개발 환경 및 장비

| 항목 | 내용 |
|---|---|
| 운영체제 | Windows 11 |
| 가상화 환경 | WSL2 |
| Linux 배포판 | Ubuntu 24.04 LTS |
| ROS2 | Jazzy |
| 카메라 | Microsoft LifeCam HD-3000 |
| 영상 처리 | OpenCV |
| USB 연결 도구 | usbipd-win |
| 카메라 장치 | /dev/video0 |

## 2. 최초 발생 문제: Ubuntu에서 USB 카메라 인식 불가

초기 개발 과정에서 Windows에 연결된 USB 카메라가 Ubuntu 환경에서 정상적으로 인식되지 않는 문제가 발생하였다.

Windows와 WSL2는 USB 장치를 자동으로 공유하지 않기 때문에, Windows에 연결된 카메라를 Ubuntu에서 사용하려면 별도의 USB 장치 전달 과정이 필요했다.

### 원인

- Windows와 WSL2 사이에 USB 장치가 자동으로 전달되지 않음.
- Ubuntu에서 카메라 장치 파일(`/dev/video0`)을 확인할 수 없는 상태 발생.
- OpenCV에서 카메라를 열기 전에 USB 장치 연결부터 해결해야 하는 상황이었다.

### 해결 방법

`usbipd-win`을 사용하여 Windows에 연결된 USB 카메라를 WSL2의 Ubuntu로 전달하였다.

USB 장치를 Ubuntu에 연결한 이후 다음 명령어로 장치 인식 여부를 확인하였다.

```bash
lsusb
```

이후 카메라 장치 파일을 확인하였다.

```bash
ls /dev/video*
```

확인 결과 `/dev/video0`가 실제 영상 캡처 장치로 확인되었다.

## 3. 두 번째 문제: 카메라 영상 수신 속도 및 안정성 저하

USB 카메라가 Ubuntu에서 인식된 이후에도 영상 수신 과정에서 추가적인 문제가 발생하였다.

### 발생 현상

- 640×480 해상도에서 영상 수신 속도가 약 2.3 FPS로 측정됨.
- OpenCV 영상 수신 과정에서 `select() timeout` 발생.
- V4L2 관련 오류 발생.
- USB/IP 연결 환경에서 영상 수신이 불안정해지는 현상 확인.
- 장시간 실행 시 JPEG 데이터 손상 메시지 발생.

### 원인 분석

USB 카메라가 Ubuntu에 연결되는 것과 안정적으로 영상을 수신하는 것은 별개의 문제였다.

특히 WSL2의 USB/IP 전달 환경에서 카메라의 해상도와 프레임 설정에 따라 영상 수신 성능이 달라지는 것을 확인하였다.

따라서 카메라의 해상도와 프레임 속도를 낮추고, MJPG 포맷을 적용하여 영상 수신 성능을 확인하였다.

## 4. 영상 수신 설정 변경 및 테스트

카메라의 영상 출력 설정을 변경하여 성능을 비교하였다.

### 카메라 해상도 및 포맷 설정

```bash
v4l2-ctl -d /dev/video0 --set-fmt-video=width=320,height=240,pixelformat=MJPG
```

### 프레임 속도 설정

```bash
v4l2-ctl -d /dev/video0 --set-parm=10
```

### 설정 확인

```bash
v4l2-ctl -d /dev/video0 --get-fmt-video
```

### 영상 스트리밍 테스트

```bash
v4l2-ctl -d /dev/video0 --stream-mmap=3 --stream-count=30 --stream-to=/dev/null
```

### 테스트 결과

| 테스트 항목 | 결과 |
|---|---|
| 초기 해상도 테스트 | 640×480 |
| 초기 영상 수신 속도 | 약 2.3 FPS |
| 변경 해상도 | 320×240 |
| 변경 영상 포맷 | MJPG |
| 요청 프레임 속도 | 10 FPS |
| V4L2 스트리밍 테스트 | 약 10.1 FPS |

해상도와 영상 포맷을 변경한 후 V4L2 스트리밍 테스트에서 약 10.1 FPS를 확인하였다.

다만 OpenCV를 통한 장시간 영상 수신에서는 JPEG 데이터 손상 메시지와 V4L2 timeout이 여전히 발생하여 추가적인 안정성 검증이 필요한 상태이다.

## 5. 문제 해결 과정 요약

| 단계 | 발생 문제 | 조치 및 결과 |
|---|---|---|
| 1단계 | Ubuntu에서 USB 카메라 인식 불가 | usbipd-win으로 USB 장치 전달 |
| 2단계 | 카메라 장치 파일 확인 | `/dev/video0` 확인 |
| 3단계 | 영상 수신 속도 저하 | 해상도 및 출력 포맷 변경 |
| 4단계 | V4L2 스트리밍 속도 저하 | 320×240 MJPG, 10 FPS 설정 |
| 5단계 | 장시간 영상 수신 불안정 | JPEG 손상 및 timeout 추가 확인 필요 |

## 6. 결론 및 향후 개선 방향

이번 문제를 통해 WSL2 환경에서는 USB 장치가 정상적으로 인식되는 것뿐만 아니라 영상 스트리밍의 안정성도 별도로 확인해야 한다는 점을 확인하였다.

현재는 usbipd-win을 이용한 USB 카메라 연결과 V4L2 스트리밍 테스트까지 진행하였다.

향후에는 다음 사항을 추가로 검증할 예정이다.

1. OpenCV에서 장시간 영상 수신 시 FPS 안정성 확인
2. JPEG 데이터 손상 및 V4L2 timeout 발생 원인 분석
3. 카메라 해상도와 FPS 조합별 성능 비교
4. YOLO 객체 인식 및 MediaPipe 손 추적을 함께 실행했을 때의 전체 처리 속도 측정
5. ROS2 카메라 노드와 영상 처리 노드 간 통신 안정성 확인

최종적으로 객체 인식과 손가락 추적을 동시에 수행할 수 있는 안정적인 카메라 입력 환경을 구축하는 것을 목표로 한다.
